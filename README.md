# 깃발대항전 봇

「깃발대항전 봇 구현 지침서 v1 — 경제 우선 · 그물 라인 · 정크무빙 0」을 따라 처음부터 구현한 Python 봇입니다. 표준 라이브러리만 씁니다.

## 실행과 제출

```
python3 bot/main.py                  # 서버와 같은 stdin/stdout 프로토콜
tools/package.sh dist/submission.zip # 제출 ZIP (최상위에 submission.json + *.py)
python3 tests/test_boundary.py       # 부록 A 경계선 테스트 벡터
```

campus-sim으로 대전하려면 봇 폴더를 그대로 넘기면 됩니다.

```
cd ~/campus_sim
python3 sim.py play /path/to/kyhackathon/bot bots/pool/rush --seed 1 --replay r.html
python3 sim.py tour /path/to/kyhackathon/bot bots/pool/rush bots/pool/sieger --vs --games 50 --variant mixed --workers 2
python3 sim.py check dist/submission.zip
```

## 지침서와 다르게 해석·보완한 부분

구현하며 대전 로그로 확인한 문제를 고친 결과입니다. 모두 `params.py`나 해당 함수 주석에 근거를 남겼습니다.

1. **정규 좌표계 (`canon.py`).** (y, x) 순 동률 처리가 진영마다 달라 Y·K가 거울상 결정을 내지 못했습니다. K면 좌표를 돌려서 처리하고, 건물 순회도 id가 아니라 정규 (y, x) 순으로 합니다. 그래서 같은 봇끼리의 미러전은 무승부가 됩니다.
2. **깃발 여유 `P-FLAG_MARGIN_OWN` (13.3).** 우리 건물 위에서는 E1 > 0일 때만 여유 1을 더합니다. E1 = 0이면 상한이 0이라 뽑힐 위험이 없기 때문입니다. 그대로 두면 본진 출구의 우리 건물을 지날 때마다 호위가 필요했습니다.
3. **P1c 경계 칸 슬롯 (11.5).** 마감이 붙은 P1c 슬롯과 함께 마감 없는 P2 몫을 같은 칸에 둡니다. 마감 안에 닿는 병력이 없으면 칸이 계속 비어 있었기 때문입니다.
4. **라인 배치율 (10.7).** 상대가 점거한 경계 칸은 임시 2선(11.5)이 맡으므로 분모에서 뺍니다. 빼지 않으면 상대 더미가 경계 칸 몇 개에 앉는 것만으로 라인이 영영 완성되지 않아 전진·후퇴 판단이 시작되지 않았습니다.
5. **area 예약 (12.4).** "area 예약은 반경 밖으로 못 나가게 할 뿐"이므로, 반경 안에 머무는 이동이면 같은 등급의 다른 슬롯도 그 인원을 가져갈 수 있게 했습니다. 겹치는 경주 수비 슬롯끼리 병력을 서로 묶어 두던 문제가 사라졌습니다.
6. **분대 (17장).**
   - 동시 분대 상한은 3이고, 실제 제한은 여유 병력입니다. 여유는 직전 턴 P0~P2 point 슬롯의 칸별 수요 합을 빼서 셉니다.
   - 라인 완성 전이면서 45턴 전(PH1·PH2)에는 공학관·학생회관 분대만 냅니다. 이 시기에 상대 쪽 보급소·병원 분대가 라인을 비우는 문제가 있었습니다.
   - WAIT 상태는 깃발이 대기 칸에서 밀려나도 대기 턴을 세고, MOVE에도 시간 상한을 둡니다.
7. **TELE 경유 (12.3·15장).** 배정 비용에 넣지 않고 경로 단계에서 처리합니다. 걸어가는 것보다 "역 s1 → TELE → 역 s2 → 목표"가 인원당 2턴 이상 빠르면 s1 쪽으로 걷습니다. 대기열은 s1에 모인 인원 ÷ 5로 셉니다.
8. **시간.** 개선 패스(⑥)는 후보 40그룹까지만 보고, 장부는 같은 칸·같은 임무 그룹을 합쳐 기록합니다. 동률은 `id()` 대신 일련번호로 처리해 결정성(INV-12)을 지킵니다.

## 아직 구현하지 않은 부분

- 16.4 오프닝 계획기의 개선 단계(차선 간 건물 옮기기·순서 바꾸기)와 규칙 차선 A~E. 지금은 탐욕 구성만 있습니다.
- 16.6 정찰병 (`P-SCOUT` 기본 끔).
- 18.2 마감 중 상대 생산지 봉쇄.
- 19장 상대 유형별 조정 중 "사냥꾼"(요격으로 깃발 2명 이상 손실 → 여유 1, 빈 측면 습격 끔)만 넣었습니다.
- 21.2 경기 지표는 마지막 턴 `END` 로그 한 줄로만 남깁니다.
- 22.1·22.2 단위 테스트는 부록 A 경계선 테스트만 있습니다.

## 디버그 도구

```
# 우리 봇은 같은 프로세스, 상대는 하위 프로세스. --dump N 으로 N턴의 슬롯·배정·깃발 상태 출력
python3 tools/debug_run.py --opp bots/pool/escort --seed 6 --variant mixed --team Y --dump 30 --quiet
python3 tools/stress.py --seeds 5
```

봇 stderr에는 턴마다 한 줄(21.1 형식)이 남습니다. 예:
`T30 MFIX dP-1.0 A-9 R13 W100/109 F5/6 S12/23 Fr12/6 L-2-2-2-2-2-2-2 U0,0 mv60 rv4/0 ...`

| 필드 | 뜻 |
|---|---|
| M | 모드 |
| W, F, S | 전투병, 깃발, 점수 (우리/상대) |
| Fr | 경계 칸 / 배치된 칸 |
| L | 섹터 수준 |
| U | 미충족 P0, P1 |
| rv | 역행 시도 / 사유 없음 |
| sw | 맞교환 취소 |
| sp | 생산 |
| tl | TELE |

첫 줄 `INITMAP`은 실제 맵 수집용 INIT 블록입니다.
